同源工单/工艺结构未变时，同步库内修订的未开工工序、工时、允许设备、甘特和目标参数。已执行进度、故障/恢复状态、现有库存和本地确认修改保留，原运行ID、计划日期和下游关联保持。源与本地对同一参数均有不同修改时提示冲突；另一份计划或工艺结构变化需明确归档并启用新运行，不继承不相干的进度。

每15秒检查绑定来源；有变化提示「库内有更新」，用户预览后确认，不自动覆盖运行。预览5分钟有效，确认时重读源指纹、约束版本及最新进度；源或现场条件变化则重新预览。完整约定见[数据/API](产业链运维系统接口与数据约定.md)。

## 标准关联中的新增参数

标准基线不是原模块已产生的联合计划。关联参数保存在 binding.json，页面「生产来源 → 来源与关联」可核对：

- 原部件计划未记录件数；此标准关联明确设为每种部件同批5件，满足原路线合计5件需求。原工时仍是整批工时，未按5件重复放大。
- 组装逐台执行原9工序；部件与组装关系在任务前置和投入产出中明确连接。外购消耗暂按每台每种1单位，须依据实际BOM确认。
- 连续7天是标准模拟日历，未宣称读取了真实班次。
- 保留物流路线的相对窗口和道路时间，将运输日固定到全链可就绪后的下一工作日08:00，避免历史运输日期早于新模拟生产日期。
- 原资料没有客户交付承诺，due_at 保持空值；显示交期待确认，不能用窗口、算法估计或0延期代替真实承诺。

因此该标准基线是可解释、可追溯的同源关联模拟，仍需业务确认新增参数。不是将各模块正在运行的实例自动合并。

## 已保存生产计划的直接接入

页面「生产来源 → 库内已排程计划」可选择原计划和具体算法，确认时间单位，预览后启用执行副本。API为 GET /api/operations-tools/plans/sources、POST /plans/preview、POST /plans/activate。生产来源现在为默认入口，标准关联计划仅作明确选择的演示备用，不再默认启用固定计划。

导入保留原工单、设备允许集合、工时、甘特和可用的BOM/库存。缺组装与配送关系时只启用生产范围，相应环节显示未绑定；原工单未给BOM则明确标记。工单目标使用其最后工序，不将部件完工计为整机交付。缺设备、含未适配连续耗料、工单/工序重名无法唯一匹配或已保存甘特违规时拒绝启用。

预览返回原数据指纹，启用重新读取并校验；原计划、算法结果有变化须重新预览。不写原 work_orders、production_execution、设备布局或实际库存；调整作用于明确标记的运维副本。

## 原实例如何处理

旧 REFRIGERATOR-STANDARD-v1 示例不能只改名字伪装成原设备。替换时把旧实例、进度、事件及切换时刻完整归档到 operations_runs，再创建对齐后的实例；旧故障不擅自映射到原设备。旧示例兼容替换须核对 previous_run_id。已对齐实例可同步同源未开工任务；切换另一份生产计划必须明确确认并归档，不能直接覆盖。

新基线共93项任务：44生产、45组装、装车/两次客户服务/返场4项；27项资源：8生产设备、18组装工位、1辆原路线车辆。标准日期固定后仍按服务器真实时钟持续执行。
