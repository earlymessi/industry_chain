# 系统配置与启动指南（首次使用）

本文档面向**第一次部署与使用**本系统的用户，说明环境准备、配置项、启动顺序、访问入口与常见问题。

系统全称：**基于强化学习的产业链分布式资源适配与调度管控系统**。

---

## 1. 系统由哪些部分组成

| 模块 | 技术栈 | 是否随主程序一起启动 | 说明 |
|------|--------|----------------------|------|
| 主控台与统一壳层 | FastAPI + Vue 3 | 是 | 左侧菜单进入各子系统，端口 **8008** |
| 生产资源管控 | FastAPI + MongoDB | 是 | 看板、排程、数据中心、智能助手等 |
| 供应链全局调度 | Scheduletool（Flask 挂载） | 是 | 挂载在 `/scheduletool`，Hub 内嵌访问 |
| 组装资源管控 | MASA-QMIX（Flask 挂载） | 是 | 挂载在 `/masa-qmix`，Hub 内嵌访问 |
| 外协供应商管控 | FastAPI + 本地 JSON | 是 | 外购/外协库存与模拟发运 |
| 物流资源管控 | zhenjie（Flask 挂载） | 是 | 集成多周期车辆路径优化，后端 `/logistics-vrp`；侧边栏含订单、实验、结果、图表与地图 |
| 知识库问答 | Vue + FastAPI RAG 子进程 | 是 | 与主后端同端口 **8008**，无需 Streamlit |
| 知识库文档管理 | FastAPI + RAG 子进程 | 是 | 「产业链知识库 → 文档管理」标签 |

**推荐理解方式**：日常只需启动 **MongoDB + `python main.py`** 即可使用全部功能（含知识库问答与文档管理）。Streamlit 为历史可选方案，**已不再需要**。

---

## 2. 环境要求

- **操作系统**：Windows 10 / 11（本文命令均为 PowerShell）
- **Python**：3.10 及以上
- **Node.js**：18+ 与 npm（用于构建前端）
- **MongoDB**：本地服务，默认 `mongodb://127.0.0.1:27017`
- **磁盘**：建议预留 2GB+（含向量库与依赖）

可选能力依赖：

- **大模型 API Key**（DeepSeek / 智谱）：生产模块「智能助手」、知识库 RAG
- **向量嵌入 Key**（智谱 `LLM_API_KEY` 或 DashScope）：知识库入库与检索

## 3. 第一次安装（完整步骤）

在**项目根目录** `metaforge` 下执行。将路径替换为你本机实际路径。

### 3.1 克隆或解压项目

```powershell
cd D:\Users\Administrator\Desktop\软著\metaforge
```

### 3.2 创建 Python 虚拟环境并安装依赖

```powershell
python -m venv .\metaforge-test-env --system-site-packages
.\metaforge-test-env\Scripts\Activate.ps1

pip install -r .\requirements.txt
pip install -e . --no-build-isolation --no-deps
pip install flask flask-cors gym==0.26.2
```

说明：

- `requirements.txt`：FastAPI、MongoDB 驱动、`python-multipart`（文档上传）等
- `flask` / `flask-cors` / `gym`：挂载 **MASA-QMIX**、**Scheduletool** 所需
- `flask` / `folium`：车辆路径模块所需，已包含在根目录 `requirements.txt`。订单使用独立数据库 `zhenjie_vrp`，复用 `MONGO_URL` 连接；也可用 `ZHENJIE_MONGO_URI` 单独指定。该模块无需另启 5000 端口，客户 CSV 与实验产物均保存在 `zhenjie/`。路网计算需要访问 OSRM，地图底图与原页面 CDN 资源需要联网。

> 若使用 Anaconda 等全局环境，也需确保已安装上述包，尤其是 **`python-multipart`**，否则启动时会报错。

### 3.3 配置环境变量

**（1）项目根目录 `.env`**

```powershell
copy .env.example .env
```

用编辑器打开 `.env`，至少按需填写：

```env
# 后端端口（默认 8008，一般不改）
METAFORGE_PORT=8008

# 智能助手（生产模块）— 填其一即可
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_BASE_URL=https://api.deepseek.com

# 未配置 LLM 时助手会回退为规则模式，系统仍可启动
LLM_ENABLED=1
LLM_FALLBACK=rule

# MongoDB（与默认一致可省略）
# MONGO_URL=mongodb://127.0.0.1:27017
# MONGO_DB=metaforge_mes

# 组装模块入口（默认即可）
MASA_QMIX_UI_URL=/masa-qmix/
```

**（2）知识库 RAG 配置 `rag\langchain-agent\.env`**

```powershell
copy .\rag\langchain-agent\.env.example .\rag\langchain-agent\.env
```

填写对话与向量嵌入密钥（知识库问答、文档入库需要）：

```env
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1

# 向量嵌入（智谱示例）
LLM_API_KEY=你的智谱密钥
EMBEDDING_MODEL=embedding-2
```

知识库原始文档目录：`rag\langchain-agent\data\`  
向量库与清单：`rag\langchain-agent\storage\`

### 3.4 构建前端

```powershell
cd .\frontend
npm install
npm run build
cd ..
```

构建产物输出到 `tests\templates\dist\`，由 `main.py` 统一托管。

### 3.5 确认 MongoDB 已安装并启动

```powershell
Start-Service MongoDB
```

若无 Windows 服务，请确保本机 `27017` 端口可连接。

## 4. 启动系统

### 4.1 标准启动（必做）

```powershell
cd D:\Users\Administrator\Desktop\软著\metaforge
.\metaforge-test-env\Scripts\Activate.ps1
Start-Service MongoDB

cd .\tests
python .\main.py
```

看到类似 `Uvicorn running on http://127.0.0.1:8008` 且无报错，即启动成功。

若已在 `tests` 目录，直接：

```powershell
python .\main.py
```

### 4.2 知识库问答（Streamlit 嵌入）

**「产业链知识库 → 知识库问答」** 在 Hub 内通过 **iframe 嵌入 Streamlit**（与早期可用版本一致）；**「文档管理」** 仍为 Vue 原生页，走主后端 `8008` 的 `/api/rag/*`。

主后端启动时会尝试自动拉起 Streamlit（默认 `http://127.0.0.1:8501`）。若嵌入页空白，可手动：

```powershell
.\scripts\start_rag_streamlit.ps1
```

Hub 入口：`http://127.0.0.1:8008/new-ui/home/knowledge`

### 4.3 启动后建议自检

| 检查项 | 地址 / 操作 | 期望结果 |
|--------|-------------|----------|
| 主界面 | `http://127.0.0.1:8008/new-ui/home` | 产业链主控台正常显示 |
| 生产看板 | 左侧 → 生产资源管控 → 生产看板 | 页面可打开，顶栏显示 MongoDB Online |
| 供应链 | 左侧 → 供应链全局调度 | 子菜单可展开；Scheduletool 在线时可进入 |
| 组装 | 左侧 → 组装资源管控 | MASA-QMIX 在线时可进入 |
| 知识库文档 | 知识库问答 → 文档管理 | 切换标签后自动加载列表（首次可能需十几秒） |
| RAG 状态 | 文档管理页右上角 | 「RAG 在线」表示配置正确 |

## 9. 常见问题

### 启动报错：`python-multipart` 未安装

文档上传接口依赖此包：

```powershell
pip install python-multipart
```

### MongoDB 连接失败

```powershell
Start-Service MongoDB
```

检查 `.env` 中 `MONGO_URL` 是否与本机一致。

### 页面无样式或菜单为旧版

重新构建前端并强刷：

```powershell
cd .\frontend
npm run build
```

### 供应链 / 组装菜单显示离线

- 确认 `Scheduletool`、`MASA-QMIX` 目录在项目根目录下
- 确认已安装 `flask flask-cors gym`
- **重启** `python main.py`

### 知识库问答无响应或报错

1. 确认 `rag\langchain-agent\.env` 已配置对话与嵌入 Key
2. 文档管理页右上角应显示 **「RAG 在线」**
3. 若刚更新 `data\` 下知识文件，在问答页点击 **「重建知识库」**
4. 确认已 `npm run build` 并重启 `python main.py`

### Chroma 报错 `pyo3_runtime.PanicException`

若出现类似 `range start index ... out of range` 的 Chroma Rust panic，通常是本地向量索引损坏或版本切换导致。

建议处理顺序：

1. 在知识库页面点击 **「重建知识库」**
2. 若仍失败，停止后端后删除 `rag\langchain-agent\storage\chroma_db`
3. 重新启动后端并重新入库文档

### RAG 检索 A/B 对比（扩展开关）

用于对比“关闭/开启 LLM 查询扩展”的检索命中差异：

```powershell
cd .\rag\langchain-agent
python .\scripts\ab_eval_rag_retrieval.py
```

可选：指定问题集（每行一个 query）

```powershell
python .\scripts\ab_eval_rag_retrieval.py --queries-file .\data\queries.txt
```

输出文件默认位于：`rag\langchain-agent\storage\ab_eval_rag_retrieval.json`

### 文档管理列表为空或需手动刷新

- 确认 `rag\langchain-agent\.env` 已配置嵌入 Key
- 首次打开「文档管理」会加载 RAG 子进程，**等待十几秒**
- 确认已 `npm run build` 到最新前端
- 文档文件位于 `rag\langchain-agent\data\`

### 缺少 `python-multipart` 以外的依赖

重建虚拟环境：

```powershell
Remove-Item -Recurse -Force .\metaforge-test-env
python -m venv .\metaforge-test-env --system-site-packages
.\metaforge-test-env\Scripts\Activate.ps1
pip install -r .\requirements.txt
pip install -e . --no-build-isolation --no-deps
pip install flask flask-cors gym==0.26.2
```

### 8008 端口被占用

关闭旧的后端进程后重新启动：

```powershell
cd .\tests
python .\main.py
```

可使用 `scripts\cleanup_backend.ps1`（若项目提供）清理残留进程。

### Gym 弃用警告

启动时可能出现 Gym 提示，**不影响当前功能**，可暂时忽略。

## 12. 产业链运维系统（2026-11-10 首版）

入口为左侧 **产业链运维系统**：`http://127.0.0.1:8008/new-ui/home/operations-tools`。与主系统共用 FastAPI 和 MongoDB，不另开运行时端口。修改代码后先在 `frontend` 目录执行 `npm run build`，再重启 `tests/main.py`。

首次点击「选择已排程计划」，从库内选择生产计划及保存算法，预览校验后启用。之后通过顶部「生产来源」检查库内更新、预览并同步；同源同步保留已执行进度和原计划日期。标准计划仅在明确选择「演示基线（备用）」时使用。主页面按四环节和实时/今日/7天/4周展示计划，右侧「运维操作」直接修改参数并生成调整计划。后台与页面解耦，关闭页面不停止执行；服务器及 MongoDB 需持续运行。

需要把生产、组装与配送串成同一批执行计划时，点击顶部「计划衔接」：选择前序结果、确认部件及用量、填写时间映射和交接参数，再预览并明确启用。配置可保存复用，当前运行仅在确认后归档切换。完整操作与兼容边界见[计划衔接实施记录](产业链计划衔接实施记录.md)。

`.env` 可配置：

```dotenv
OPERATIONS_ENABLED=1
OPERATIONS_SOLVER_TIMEOUT=30
```

`OPERATIONS_ENABLED=0` 后重启主后端，可停用后台执行及写入命令、保留状态与历史；再次启用后模拟执行追赶当前时间。不能把“页面关闭”当作停用。求解器采用按需创建的独立 Python 子进程，超时限制5～60秒，超时不修改原执行计划。部署建议单个 Uvicorn worker；维护者租约为15秒，异常退出重启后可能需等待原租约到期再继续。

运行数据保存在当前 `MONGO_DB_NAME` 下的 `operations_*` 集合，和原 MES/库存隔离。活动快照不设过期，替换后的进度快照两天后清理，事件与实例归档保留。备份应包含 heads、states、commands、adjustments、history、runs 的一致截面；建议停用执行并停止主后端后再用 MongoDB 工具备份整个数据库，恢复时同样保持服务停止，不只恢复活动指针。

健康查询：`GET /api/operations-tools/current`。online 表示运行维护正常，follower 表示当前进程不是维护者，disabled 表示已停用，offline/error 表示检查数据库、租约或后台异常；不要通过重新激活计划“修复”同步问题。恢复服务后先确认原 `run_id` 和生效日期未变化。

车辆路径模块若提示缺少 `folium`，在实际启动 Python 的相同环境安装 `requirements.txt` 中该依赖并重启；不要在另一虚拟环境安装后继续使用旧解释器。

生产默认读取库内已保存排程，不固定计划ID。已有跨环节关联在同源同步时保留；任意新生产计划缺下游关联则标未绑定。另一份计划或工艺结构变化须先确认归档再启用新运行，不能把旧进度套给新工单。现场设备/MES/GPS 自动采集尚未接通。详见[基线修复记录](产业链运维基线对齐修复记录.md)、[交付与验收](产业链运维系统首版交付与验收记录.md)及[数据/API](产业链运维系统接口与数据约定.md)。
